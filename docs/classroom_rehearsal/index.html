01

실물 SLAM

움직이지 않을 것부터 고정하기

매핑할 때 택배가 LiDAR 스캔면에 잡히면 정적 지도에 장애물로 남을 수 있습니다. 집은 뒤 빈자리로 다시 접근할 때 길을 막는 원인이 됩니다.

맵은 택배 없이 저장 → 택배 배치 → 위치 추정·접근점 확인 순서를 권합니다. 계속 남는 받침대는 먼저 배치하고, 함께 들어 올릴 팔레트는 택배와 같이 취급합니다.

192 Gazebo

현재 강의실 시뮬은 맵 자동 생성

기존 generate_classroom.py가 월드의 고정 충돌체로 classroom_map.yaml/pgm을 만듭니다. 이 시뮬에서는 SLAM을 따로 돌릴 필요가 없습니다.

택배는 classroom_nodes.py가 따로 생성합니다. 고정물 배치와 접근점을 classroom.yaml에서 함께 고친 뒤 러너로 월드·지도를 다시 생성합니다.

이미 택배가 들어간 맵을 저장했다면?

택배를 치우고 해당 영역을 다시 관측해 지도 자체에서 자국이 사라졌는지 확인한 뒤 재저장하세요. 고정 구조만 다시 매핑하는 방법도 있습니다. costmap clear는 원본 PGM의 택배 자국을 지우지 않습니다. 이는 정적 지도와 실시간 장애물 레이어가 분리된 구조에 따른 판단입니다. Nav2 Static Layer ↗

03

무엇을 먼저 배치할까

맵 전에 고정 / 맵 뒤에 추가 / 실물 확인
첫 연습은 택배 1개와 402 송장으로 시작. 두 번째 택배는 선택 규칙을 확인할 때 추가합니다.
항목언제 / 어떻게미리 고려할 점
벽·칸막이·책상맵 전에 고정연습 내내 같은 위치 유지. 스캔 높이에서 면이 보이는지 확인. 실제 책상은 상판 밑으로 LiDAR가 지나가 다리만 보일 수 있습니다.
버튼판·층수 화면지지대부터 고정호출판과 층 버튼판은 기존안의 1 m 간격으로 시작. 높이는 티칭된 팔 끝에 맞춤. 화면은 보기 자세에서 정면에, 지지대·케이블은 회전·후진 경로 밖에 둡니다.
택배·들리는 팔레트맵 저장 뒤 배치포켓과 송장을 접근 방향으로 향하게. 처음에는 1개만 고정 위치에 놓고 빈 상자로 검증. 함께 집는 팔레트는 이동물, 계속 남는 받침은 고정물입니다.
택배 자리·보관 구역 테이프맵 전 부착 가능원래 내려놓을 사각 자리와 후보 구역을 구분. 실제 조명에서 카메라로 읽히는 색·두께 확인. 바닥 테이프만으로 SLAM 경계가 만들어지지 않습니다.
송장·숫자·주변 소품카메라로 사전 시험402 → 4층부터 연습. 무광 흰 라벨·굵은 검은 숫자·충분한 여백. 기존안의 28 × 18 cm는 규격 A5(21 × 14.8 cm)와 다르므로 “A5”만 보고 출력하지 말고 실제 인쇄 치수·카메라 판독으로 확인합니다.
주행·회전·도킹 공간적재 상태로 확인로봇 몸체 외에 지게팔·택배·펼친 팔의 전체 궤적 확인. A 앞 직선 진입·후진과 B의 90° 회전 공간 확보. 시뮬 치수로 실물 여유를 단정하지 않습니다.
운영자·노트북·케이블구역 밖에 고정층수 화면을 바꾸는 담당자 1명. 관객은 시연 경로 밖, 전원·영상 케이블은 바퀴 경로 밖으로 정리. 매핑 중 사람은 주요 벽면을 가리지 않습니다.

낮은 물체는 LiDAR가 못 볼 수 있음

2D LiDAR는 스캔면과 교차하는 물체를 봅니다. 낮은 택배·팔레트·바닥 케이블이 스캔면 아래면, 맵에서도 실시간 costmap에서도 안 보일 수 있습니다. 실제 스캔과 카메라로 확인하고 그런 물체를 주행 경로에 두지 마세요.

LiDAR 높이·로봇 폭은 hardware_spec.md가 기준입니다. 현재 문서와 새 시뮬의 기하가 다르므로 현물 측정으로 확인해야 합니다.

택배를 적재한 뒤의 시야도 확인

택배 윗면·리프트가 LiDAR 또는 팔 카메라를 가리는지, 송장·버튼·층수 화면이 적재 후에도 보이는지 확인합니다. 빈 차체에서 성공한 버튼 누르기가 적재 상태에서도 되는지 별도로 연습하세요.

시뮬의 싣기·내리기는 붙이기/놓기 mock입니다. 실물의 포켓 정렬·마찰·하중 검증을 대신하지 않습니다.

04

코드에는 무엇을 준비할까

기존 동작과 추가 준비를 구분
준비할 설정 / 동작현재 확인 범위이번 연습에서 할 일
지도·좌표·도착 방향시뮬 설정 있음classroom.yaml의 poses에 start / a_approach / b_call_view / b_floor_view / drop_predock / end가 있습니다. 실제 매핑 후에는 지도 버전과 map 좌표를 묶어 별도 등록하세요. 기존 건물 F1/F2 전환 설정을 그대로 쓰지 마세요.
택배 선택·송장시뮬 구현 확인보관 구역 안 후보만 허용. A를 보고 도착하면 turn_before_scan_rad=0을 사용합니다. 3자리·첫 자리 2/3/4·동일 번호 새 프레임 3개를 확인한 뒤 목표층 확정. 읽기 실패 시 임의로 4층을 넣지 않습니다.
도킹과 내려놓기시뮬 구현 확인Nav2는 물체 앞 접근점까지, 마지막 포켓 정렬은 카메라·근접 확인으로 진행. 좌표만으로 정밀 삽입하지 않습니다. 복귀 후 내려놓기는 원래 자리 테이프 재인식. 실제 실음/해제 성공 확인은 센서·기구 검증이 필요합니다.
팔 자세·버튼 구분실물 티칭 확인 필요▲ / 4 / ▼ / 1 사이클부터 확인. “4와 1만 티칭됨”이 기존 계획의 기록이며, 현재 현물 상태는 재확인이 필요합니다. 아랫줄은 바로 위 버튼을 스치지 않게 곧게 진입·복귀. 판 구역·기호·행/열을 함께 구분하세요.
층수 화면·층 전환강의실 시뮬 분리됨목표층을 새 프레임 5개로 확인. 실제 화면 숫자 진행은 운영자가 맡습니다. 한 강의실에서 4층을 표시해도 물리 공간은 같은 지도입니다. 강의실 모드에서 실제 지도·월드 교체를 호출하지 않게 확인하세요.
적재 footprint·정지실기 적용 확인 필요적재/비적재 외곽과 돌출물 반영. Nav2 목표 취소 → 실제 속도 0 확인 후 팔·리프트 시작. /scan·odom·TF·카메라가 끊기면 정지. 도킹이 막힌다고 obstacle layer 전체를 끄지 않습니다.
부분 연습·재시작·기록통합 러너 확장 제안실기용 단계 선택·수동 확인·timeout·유한 재시도·중단 지점 기록을 준비. 재시작 전에 적재 여부·팔·리프트·로봇 위치를 다시 확인합니다. 기존 강의실 러너에 임의의 --from / --steps 옵션이 있다고 가정하지 마세요.
점유 지도는 “이게 택배다”라는 정보를 저장하지 않습니다.

지도에는 점유/빈 공간이 저장됩니다. 택배 후보 구역·번호·버튼 종류·동작 순서는 별도의 인식·미션 설정이 담당합니다. 택배를 지도에 그려 넣는 대신 보기점 → 인식 → 미세 정렬로 연결하세요.
