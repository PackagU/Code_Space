# 최종 시연 시나리오와 시스템 구조

작성일: 2026-10-07. 상태: **계획만**. 아래 흐름 가운데 실물로 동작한 구간은 2026-09-14~16의 Nav2 복도 주행 일부뿐이다. 9/16 엘리베이터 탑승·하차는 사용자 보고 기준 수동이었다. 상하차·버튼 누르기를 그날 실제로 했는지는 기록이 없다(⚠️미확인).

## 1. 목표 정의

사용자 목표(2026-10-07 지시): 지금 중간중간 사람이 조작하는 부분을 모두 없애고, 출발부터 복귀까지 사람 조작 없이 동작하는 모습을 시연한다. 핵심 수단은 로봇팔에 달린 카메라다.

이 계획에서 "완전 자율"은 다음을 뜻한다. 이 정의와 6절의 사전 준비 범위는 제안이며 사용자 확인이 필요하다(03 문서 D11).

- **시작 명령 1회 뒤 사람 입력 0회.** 키보드·브라우저·터미널 입력, 손으로 버튼 누르기, 로봇 밀기·들기, 문 잡아 주기를 모두 포함한다.
- 시작 전 준비는 허용한다. 다만 아래 6절 목록으로 고정하고 짧게 유지한다.
- 엘리베이터를 사람이 대신 호출하거나 문을 잡아 주면 그 회차는 완전 자율 성공으로 기록하지 않는다.

### 3.1 단일 소유 규칙

같은 자원을 두 프로그램이 동시에 쓰면 현장에서 원인을 찾기 어려운 고장이 난다. 다음을 지킨다.

| 자원 | 소유자 | 같이 켜면 안 되는 것 |
|---|---|---|
| 팔 시리얼 `/dev/arm_servo` | 팔 노드 | `button_arm_test/app.py --execute`, `servo_test.py`, `arm_servo_menu.py` |
| 팔 카메라 | 카메라 서비스 | `floor_reader` 단독 실행, 버튼 앱 미리보기 |
| 지게팔 시리얼 | 지게팔 노드 | `lift_uno_position_terminal.py` |
| `/cmd_vel` | 시점별 하나: Nav2 또는 미세 동작 모듈 | 텔레옵, 웹 UI(`/cmd_vel` 0 발행) |

### 3.2 안전 연동 규칙

1. 팔·지게팔이 움직이는 동안 `/mission/drive_inhibit`로 바퀴를 막는다(이미 구현된 경로를 재사용).
2. 주행 중 팔은 주행 자세, 지게팔은 끝 위치에 둔다. 택배를 실었으면 위 끝, 아니면 아래 끝이다.
3. 버튼·층·택배 판단은 새 프레임 N회와 신선도 조건을 모두 통과해야 한다.
4. 탑승·하차는 문 열림을 독립 관측해야 시작한다. 표시창 숫자만으로 시작하지 않는다.
5. 지도·좌표 설정은 고정본(`map_pins.json`)과 일치할 때만 기동한다.
6. 소프트 정지(`/nav_safety/stop`)와 물리 비상정지가 항상 우선한다. 프로그램 정지는 물리 비상정지를 대체하지 않는다.

## 4. 필요한 지점 목록

`waypoints.json`에 이미 있는 지점과 새로 캡처할 지점이다. 새 지점은 로봇을 실제 위치에 세우고 `fieldctl pose capture`로 저장한다. 지도 이미지에서 계산한 좌표를 그대로 쓰지 않는다.

| 층 | 지점 | 용도 | 현재 |
|---|---|---|---|
| F1 | 출발·복귀 표식 | S0·R8 | `f1_initial_test` 있음. 바닥 표식과 일치 여부 ⚠️미확인 |
| F1 | 보관함 관측 위치 | S1·S2 | `f1_locker` 있음. 9/16 이 goal은 실패했다 |
| F1 | 칸 1·2·3 정렬 위치 | S3 | 없음 |
| F1 | 호출 버튼 관측 위치 | S4·S5 | 없음. `f1_elevator_entry`는 이미지 계산값 |
| F1 | 표시창 관측 위치 | S6 | 없음 |
| F1·F2 지도 | 캐빈 패널 위치, 캐빈 문 방향 위치 | S7~S9·R4~R6 | `f1_elevator_inside`·`f2_elevator_inside`는 이미지 계산값이다. F2 쪽 여유 추정 0.224 m는 footprint 외접 0.39 m보다 작다 |
| F1·F2 | 하차 정지 위치 | S10·R7 | `f1_elevator_exit`·`f2_elevator_exit` 이미지 계산값 |
| F2 | 배달 위치, 하역 정렬 위치 | S11·S12 | `f2_delivery_left_room4` 있음(9/16 도착 성공) |
| F2 | 호출 버튼 관측 위치, 표시창 관측 위치 | R1~R3 | `f2_elevator_staging_v1` 있음. 9/16 이 goal 2회 실패 |

캐빈은 층마다 같은 물리 공간이다. F1 지도 기준 캐빈 자세와 F2 지도 기준 캐빈 자세의 대응을 한 번 측정해 두면, 지도 전환 때 "캐빈 안 현재 자세"를 새 지도 좌표로 옮겨 초기 위치로 쓸 수 있다. 고정 좌표 하나로 초기 위치를 주는 현재 방식보다 오차가 작을 것으로 예상한다(제안, 미검증).

## 5. 단계별 소요 시간 추정

모두 `[제안값]`(계산·추정 포함) 또는 과거 `[측정값]`이다. 현장에서 다시 재야 한다.

| 구간 | 추정 | 근거 |
|---|---|---|
| 지게팔 1회 이동 | 약 35 s `[제안값]` | 9/16 가이드의 계산값(166,400 펄스 1회 이동) |
| 상차 + 하차 지게팔 이동 | 약 70 s | 위 값 × 2 |
| 팔 누르기 1사이클 | 9 s + 응답 확인 시간 | `PRESS_CYCLE_1` 시간 합 9,000 ms |
| 복도 주행 F2 엘리베이터 → 배달 위치 | 약 244 s | 9/16 `[측정값]` 244.088 s (goal 처리 시간) |
| F1 엘리베이터 → 출발점 | 약 119 s | 9/16 `[측정값]` 119.226 s |
| 엘리베이터 대기·이동 | ⚠️미확인 | 현장 측정 필요 |

왕복 전체는 15~25분 정도로 추정한다(`[제안값]`, 엘리베이터 대기 제외 계산). 배터리 지속 시간과 함께 확인해야 한다.

## 6. 시작 전 준비로 허용하는 것

| 준비 | 이유 | 줄일 방법 |
|---|---|---|
| 배터리 확인·전원 인가 | 필수 | — |
| 로봇을 출발 표식에 놓기 | 출발 위치 추정 기준 | — |
| 택배를 칸 1·2·3 중 한 곳에 놓기 | 시연 조건 | — |
| 지게팔 아래 끝 확인 후 기준 설정 | 리미트 스위치·위치 센서가 없어 USB 연결마다 기준이 사라진다 | 아래 끝 리미트 스위치 + 자동 원점 |
| 시간 동기 확인 | RTC 배터리가 없어 시계 점프 위험(이전 TODO P3, 보관본) | 시작 스크립트에서 자동 검사 |
| 스택 기동과 시작 명령 1회 | 시작 | 원커맨드 스크립트 |

택배·보관함 칸에 인식용 표식을 붙이거나, 엘리베이터를 빈 상태로 쓰는 것을 시연 조건으로 정한다면 이 표에 추가 조건으로 적는다. 그런 조건을 숨긴 채 완전 자율이라고 기록하지 않는다.

시작 명령 뒤에는 Wi-Fi가 끊겨도 미션이 계속돼야 한다. SSH 창 안에서 직접 실행한 프로세스는 SSH가 끊기면 함께 종료될 수 있으므로, 미션 프로세스는 컨테이너 안에서 터미널과 분리해 실행한다(04 문서 F-C-02).
