# 신공학관 E2E 촬영 리허설 진행기

작성: 2026-10-21 · 브랜치 `lee/field-video-20261021` (기준 `2026-10-06` `c7e8ca8`) · 판정: 오프라인 검증 + 컨테이너 부분 검증. 실물 주행 검증 전.

## 1. 무엇을 하는가

한 터미널에서 한 명령으로 촬영 순서 전체를 진행한다. 로봇이 움직이는 단계는 운영자가 Enter 로 시작 신호를 준다. 엘리베이터 탑승·하차만 키보드로 조종한다.

```text
F1 출발 → 택배 보관함(Nav2) → 팔레트 접근(초음파 정지) → 지게팔 올림 → 후진
→ F1 엘리베이터 앞(Nav2) → 호출 ▲(팔) → [탑승 수동] → 캐빈 4(팔) → [하차 수동]
→ 4층(F2 지도) 전환 → 배달 위치(Nav2) → 지게팔 내림 → 후진
→ 4층 엘리베이터 앞(Nav2) → 호출 ▼(팔) → [탑승 수동] → 캐빈 1(팔) → [하차 수동]
→ F1 지도 전환 → 출발점 복귀(Nav2)
```

F2 지도는 실제 4층이다. 캐빈 버튼은 올라갈 때 `4`, 내려올 때 `1` 이다.

팔 자세와 누르기 동작은 Jetson 버튼 웹사이트가 가진 값 그대로 쓴다. 진행기는 팔 값을 만들거나 바꾸지 않는다.

## 3. 준비

Jetson 호스트, 저장소 루트에서 한다.

1. ROS 컨테이너(`ros2_humble`)가 켜져 있는지 확인한다.
2. 버튼 웹사이트를 팔이 실제로 움직이는 모드로 켠다. 진행기는 두 모드 모두 같은 HTTP API 를 쓴다. 미리보기 모드면 시작을 거부한다.
   - 직접 시리얼(9/16 방식, `--execute --field-approved`): base·Nav2 가 꺼져 있어도 진행기가 켤지 묻는다.
   - ROS 팔 노드(10/9 방식, `--ros-arm`): `start_field_navigation.sh` 가 팔 노드가 있으면 Nav2 시작을 거부하므로 **base → Nav2(F1) → 팔 노드 → 웹사이트** 순서로 먼저 켠다. 순서가 틀리면 진행기가 이유를 말하고 멈춘다. 이 모드에서는 `--nav-restart` 를 쓸 수 없다.
3. 지게팔 Uno USB 를 꽂는다. 지게팔 터미널(`lift_uno_position_terminal.py`)은 켜지 않는다. 같은 포트를 진행기가 연다. 두 프로그램은 같은 잠금 파일을 써서 하나가 열려 있으면 다른 쪽이 거부된다.
4. 초음파 센서가 지게팔 Uno 에 붙어 있으면 따로 할 일이 없다. 별도 아두이노면 `--ultrasonic-port` 로 포트를 준다.

## 5. 화면 조작

| 화면 | 키 |
|---|---|
| 로봇 단계 시작 전 | Enter 시작 · `t` 키보드로 위치 보정 후 다시 · `s` 사람이 대신함(기록됨) · `q` 중단 |
| 실패 뒤 | `r` 다시 · `t` 보정 후 다시 · `s` 사람이 대신함 · `q` 중단 |
| 수동 조종 단계 | Enter 조종 시작 · 선택 단계는 `n` 건너뜀. 조종 중 `w/s/a/d`, `k`/Space 정지, `z` 감속, Ctrl+C 로 조종 끝 |
| 버튼 누른 뒤 | Enter 불 켜짐 · `r` 다시 누르기 · `h` 사람이 눌렀음 |
| 아무 때나 | Ctrl+C = 즉시 정지(소프트 정지 + 지게팔 `!` + 팔 중지) 후 메뉴 |

실패하면 진행기가 먼저 정지를 건다. Nav2 goal 은 실패 시 costmap 을 비우고 자동으로 한 번 더 보낸다(이 자동 재시도도 판정의 재시도 수에 들어간다). 물리 비상정지는 항상 우선이다.

점검 단계는 어떤 단계를 고르든 맨 먼저 정지를 건다. 직접 구동(키보드 조종·직진·초음파 접근) 전에는 정지를 건 채로 두 가지를 확인한 뒤에만 정지를 푼다. Nav2 구동 action 에 살아 있는 goal 이 없어야 하고(상태 토픽에 보이는 진행·취소 중 goal 과 전체 취소 응답에 나온 goal 이 모두 끝난 것을 볼 때까지 기다림, 취소 응답이 없으면 거부), `/cmd_vel` 발행자가 Nav2 말고는 없어야 한다(웹 UI·다른 텔레옵이 있으면 거부). 지게팔은 실패하면 `!` 를 보내고 STATUS 로 멈춘 것을 확인한다. 확인이 안 되면 이후 지게팔 동작을 막고 물리 비상정지를 안내한다. 키보드 조종이 비정상 종료하면 실패로 처리하고, 하차 단계는 퇴장 표식 위에 섰는지 운영자가 확인해야 다음 지도 전환으로 넘어간다.

## 6. 초음파 센서

진행기는 아두이노가 보내는 거리 줄을 읽는다. 권장 형식은 아래 한 줄을 10 Hz 이상으로 내보내는 것이다.

```text
US distance_cm=23.4
```

`DIST:23`, `ultrasonic 23.4`, STATUS 줄 안의 `us_cm=23.4` 도 읽는다. 지게팔 Uno 에 같이 붙이면 펌웨어가 위 줄을 섞어 보내도 지게팔 응답과 구분한다.

- S03 은 초음파 값이 `stop_cm`(제안값 8 cm) 이하가 되면 멈추는 저속 전진(0.03 m/s, 최대 0.60 m)이다.
- 값이 0.5 초 넘게 끊기면 즉시 멈추고 실패 처리한다. 최대 거리까지 가도 기준 거리에 못 닿아도 실패다.
- 지게팔 단계 앞뒤 초음파 값을 기록에 남긴다(택배 실림 판단 기준을 정하는 자료).

## 8. 판정과 기록

끝나면 `logs/field_video/<시각>_<label>/summary.md` 에 단계표와 판정이 나온다.

- **한 번에 통과**: 재시도·보정·사람 개입이 모두 0. 이 순서로 촬영한다.
- **개입 있음**: 표에서 시도 2 이상, 보정 1 이상, `MANUAL` 단계를 먼저 손본다.

rosbag 은 `fieldctl record` 로 함께 녹화한다(`--no-record` 로 끔).

## 9. 알려진 한계

- Nav2 를 켠 채 텔레옵하는 방식은 실물에서 처음이다. 진행기는 goal 취소 뒤에만 텔레옵을 열고, 텔레옵이 끝난 것을 확인한 뒤에만 다음 goal 을 보낸다. 첫 리허설에서 탑승 구간 주행이 끊기지 않는지 본다.
- 지도 교체는 컨테이너의 실제 `map_server` 로 검증했다(F2 교체 뒤 지도 검사 PASS, F1 검사 FAIL). 진행기는 `/map` 이 요청한 지도 파일과 크기·해상도·원점까지 같고, `/global_costmap/get_costmap` 으로 받은 지금 costmap 이 같은 크기·원점이며 새 지도의 벽 칸이 90 % 이상 lethal 일 때만 성공으로 본다. costmap 비우기 실패도 실패다. 같은 지도로 다시 시도해도 확인된다. 실기 AMCL 반응은 첫 리허설에서 본다. 안 되면 `--nav-restart`(웹사이트가 `--execute` 모드일 때만 가능)로 바꾼다.
- 버튼 눌림은 사람이 불빛으로 확인한다. 팔 누르기 성공 응답은 접촉을 증명하지 않는다.
- 초음파 펌웨어 출력 형식은 아직 정해지지 않았다. 위 6절 형식으로 맞춘다.
