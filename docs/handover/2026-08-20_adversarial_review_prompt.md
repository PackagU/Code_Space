## 공격 지점 (최소 이만큼은 파고들 것 — 각 항목에 판정을 내려라)

A. 은폐 의혹: 재시도(NAV_GOAL_RETRIES) + costmap 클리어 + belief 참값 재정위(시뮬 오라클)
   + 전환 후 텔레포트 정렬의 조합이 "10/10 연속 성공"을 만들었다.
   이 회복 스택을 전부 끈 상태(retries=0, 재정위 없음)의 소수 런과 비교하면
   무엇이 드러나는가? 회복 스택이 흡수한 실패는 실기에서 어떤 형태로 돌아오는가?
   각 회복 장치를 "정당한 실기 대응의 시뮬 등가물"과 "결함 은폐"로 이분해 판정하라.

B. 통계적 주장: 10/10 연속은 실패율 상한을 얼마로 보증하는가 (신뢰구간 계산).
   "완벽히 돈다"는 주장에 필요한 표본 크기는? 분산 3회(그중 첫 시도 무결점 1회)의
   증거 가치는? 회차 duration 분산(248~732s)이 말해주는 것은?

C. 가정치 수정의 정당성: 문폭 0.9→1.0m, footprint 노즈 0.40→0.35m 는
   "테스트가 어려워서 시험지를 고친 것" 아닌가? 실측이 0.9m 로 나오면
   현재 스택은 통과 가능한가? Nav2 파라미터(inflation_radius, RPP lookahead,
   goal tolerance) 튜닝으로 원래 치수를 통과시키는 대안을 설계하라.

D. 물리 타당성: mu1=100/mu2=1.0 마찰 분리 — Gazebo ODE 에서 이 비대칭이
   만드는 부작용(회전 중 측면 슬립, 급정거 시 요 드리프트, odom 정합성)을
   검증하는 시나리오를 제시하라. "횡력 캡 1.0×체중 < 전복 임계 1.8×" 계산의
   전제(COM 높이, 폭)를 URDF 값으로 재검산하라.

E. 스크립트 품질: run_l3_world_swap_smoke.sh 는 800줄+ 단일 bash 다.
   경합 조건(트랩 중복 실행, PID 재사용, latest/ 와 run_<ts>/ 이중 상태),
   실패 경로에서 아티팩트 유실, grep 기반 판정의 취약성(로그 포맷 변경에 무방비),
   pgrep 자기 매칭류 함정을 찾아라. 유지보수 가능한 구조로의 리팩터 경로를 제안하라.

F. 보행자 모델의 검증력: 근접 0.7m 일시정지는 "피하기 쉬운 장애물"을 만들어
   동적 회피 검증력을 약화시키지 않았는가? 정지한 보행자를 로봇이 우회하는
   시나리오(실제 요구사항)와 현재 모델의 갭. amcl belief 기반 근접 판정이
   드리프트 상태에서 실패하는 경계 조건.

G. 분산 구성의 재현성: §4.5 수동 순서(리셋→스폰 확인→스모크)가 사람 손에
   의존한다. 순서 위반·부분 실패를 감지 못 하는 지점, 원커맨드화의 결계.
   Wi-Fi 복귀·IP 변경 시 fastdds XML 정합성.

H. 게이트 공백: MAX_MISSED_RATE 미설정, WITH_F3 경로 미재검증, CI 는
   오프라인만(시뮬 회귀는 로컬 수동), repeat 러너 cpu 지표 불신 —
   이 공백들이 어떤 회귀를 통과시키는지 구체 시나리오로 보여라.

## 규칙

- 모든 지적은 파일:줄 또는 로그/커밋 해시 인용 필수. 인용 없는 주장은 폐기된다.
- 각 지적에 [재현 방법 또는 검증 명령] 을 붙여라. 실행 불가능한 지적은 반쪽이다.
- 반론도 함께 써라: 저자가 방어할 수 있는 논리를 먼저 제시하고 그걸 깨라.
- 심각도: CRITICAL(실기 사고/거짓 통과) / HIGH(회귀 은폐) / MED(부채) / LOW(스타일).
- 확인하지 못한 것은 "미확인"으로 표시하라. 아는 척은 감점이다.
