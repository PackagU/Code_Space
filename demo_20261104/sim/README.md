# 강의실 시연 시뮬 (11/4)

강의실 5 × 2 m 구역에서 17단계 시나리오(plan.md 3절)를 Gazebo로 한 번에 돌리고 판정하는 원커맨드 시뮬이다. 모든 판정은 **시뮬레이션 검증**이며 치수는 가정값이다.

## 실행

저장소 루트에서 실행한다. 호스트에서 실행하면 격리 컨테이너(`packagu_sim_classroom`, 내부 전용 네트워크, `ROS_LOCALHOST_ONLY=1`, 도메인 78)를 띄우고 그 안에서 다시 실행한다. 팔 카메라 렌더링에 호스트 X11 화면을 쓰므로 데스크톱 세션에서 실행한다.

```bash
python3 demo_20261104/sim/run_classroom_demo.py                 # 송장 402 → 4층
python3 demo_20261104/sim/run_classroom_demo.py --label 310     # 3층 송장
python3 demo_20261104/sim/run_classroom_demo.py --gui           # Gazebo·RViz·팔 카메라 창 (관찰용)
python3 demo_20261104/sim/run_classroom_demo.py --repeats 3 --no-record
python3 demo_20261104/sim/test_classroom.py                     # 오프라인 시험 (판독기·층 규칙·아랫줄 자세)
PACKAGU_SIM_CONTAINER=packagu_sim_classroom bash sim/real_maps/sim_container.sh down   # 정리
```

처음 실행하면 colcon build와 월드 생성을 자동으로 한다. 결과는 `logs/classroom_demo/<실행 이름>/`에 쌓인다.

기본은 **1배속**이다. 한 번 도는 데 약 11분(시뮬·실제 시간 같음)이며 이 값이 실제 시연 소요 시간의 시뮬 추정이다. `--speed 3`이나 `max`로 빠르게 돌리면 러너 노드가 카메라 영상(640×480)·TF·관절 메시지에 밀려 팔 동작 확인이 늦어지고, 그동안 정지한 차체가 캐스터 크리프로 밀려 버튼을 못 누르는 경우가 있었다(improvement_report §1.59).

| 파일 | 내용 |
|---|---|
| `report.md`, `summary.json`, `steps.csv` | 17단계 판정, 송장 판독, 월드에 등록된 버튼 누름 순서, 택배 원위치 오차, 종료점 오차, 최소 벽 거리 |
| `projector/*.png`, `projector_sheet.png` | 프로젝터에 띄울 팔 카메라 인식 화면 예시(송장·버튼·층수 판독 상자와 결과) |

## 구성

| 파일 | 역할 |

| `classroom.yaml` | 강의실·소품·화면·판독 기준 [가정값] |
| `generate_classroom.py` | 월드(강의실 벽·책상, A·B 칸막이, 바닥 테이프, 버튼판 2장, 층수 화면), Nav2 지도, 장면 정보 생성 |
| `classroom_nodes.py` | 택배 노드(송장 라벨 붙은 택배 P1·P2, 싣기·내리기 mock), 버튼·층수 화면 노드(팔 끝 접촉으로 누름 판정, 층 버튼을 누르면 한 층씩 숫자 변경 = 실물의 운영자 역할) |
| `glyphs.py` | 송장 숫자·층수 화면 판독(카메라 영상만 사용, 라벨 네 모서리 원근 보정 뒤 숫자 7개 획 영역 판정) |
| `classroom_spot.py` | 내려놓을 자리 찾기(바닥 테이프 사각형을 카메라로 찾고 LiDAR 벽 방향에 맞춤) |
| `classroom_arm.py` | 아랫줄(▼·3·4) 누르기 사이클: 누르는 자세만 8 cm 낮추고, 버튼 8 cm 뒤 같은 높이에서 곧게 들어갔다 나옴(역기구학) |
| `run_classroom_demo.py` | 원커맨드 러너 |
| `test_classroom.py` | 오프라인 시험 |

## 시뮬에서 확인해 반영한 것

| 발견 | 반영 |
|---|---|
| 호출판과 층 버튼판을 0.45 m 간격에 두면 ▲를 찾다가 층 버튼판 캡을 골라 누름 | 두 판 1 m 간격(y 1.6 / 0.6) |
| 아랫줄 버튼을 누르고 빠질 때 바로 위 버튼을 스침(4를 누르고 2가 두 번 눌림) | 아랫줄 사이클은 버튼 8 cm 뒤 같은 높이에서 곧게 들어갔다 곧게 나옴 |
| 갈색 책상을 택배로 검출해 '가장 오른쪽' 규칙이 책상을 고름 | 보관 구역(테이프) 안 검출만 후보 |
| 6 × 10 cm 송장 글자는 320×240 카메라에서 15 px라 판독이 흔들림 | A5 라벨·7 × 12 cm 글자, 카메라 640×480 |
| 고배속에서 러너 과부하 + 정지 중 크리프로 버튼 미접촉 | 기본 1배속, 카메라 2 Hz |
| `sim_stack` 준비 점검이 스캔 큐가 가득 차면 거짓 실패 | 점검 직전 큐 비움(강의실 스택) |
| 지도 좌표(AMCL)로 원래 자리에 내려놓으면 A벽 근처 추정 오차로 11 cm 어긋남(3번 중 2번) | 원래 자리 바닥 테이프를 카메라로 찾고 LiDAR 벽에 직각으로 들어가 내려놓음 |
| 송장 205의 '2'가 비스듬한 시점에서 기울어 보이고 획이 얇게 보여 매번 판독 거부 | 라벨 네 모서리 원근 보정 + 획 영역 평균 + 켜짐 경계 0.3 |
| 종료점 기준 0.15 m가 현장 Nav2 도착 허용(0.20 m)보다 엄격 | 0.25 m(허용 0.20 + 여유 0.05) |
| 팔이 보기 자세 중간에서 멈춤(궤적 플러그인이 점 시간을 누적 적용 + 유지 타이머가 러너 과부하로 13 s 안 돎) | `ArmLift.move()` 상속: 도달 대기 중 목표를 직접 다시 보냄 |

## 시뮬과 실물의 차이

- 층수 화면은 시뮬 노드가 바꾼다. 실물은 운영자가 로봇이 누른 숫자 키를 입력한다.
- 아랫줄 누르기 자세는 시뮬 가정 팔 기하로 계산한 값이다. 실물 팔은 Kim이 티칭해야 한다.
- 실물 버튼(종이컵)에는 램프가 없으므로 시뮬도 램프를 쓰지 않는다. 누름 확인은 후진 뒤 카메라로 캡을 다시 찾고 누른 자세가 맞았는지 계산하는 방식이며, 힘·스위치 신호는 아니다.
- 송장 글꼴은 시뮬용 블록 숫자다. 실물 라벨은 인쇄 글꼴로 만들고 같은 방식(획 자리 판정 또는 템플릿 등록)으로 다시 맞춘다.
- 팔 카메라는 시뮬만 640×480·2 Hz다(건물 시뮬은 320×240·6 Hz). 화각·장착 위치는 같은 가정값이다.
- 버튼 위치는 판 단위가 아니라 캡 위치로 고른다(시뮬 인식). 실물 인식은 숫자·화살표를 읽는다.
- 택배 싣기·내리기는 붙이기/놓기 mock이다. 접촉·하중·포켓 정렬은 검증하지 않는다.
